* Important concepts to remember for this project
** Denormalization
- delegate calculations or accumulations to write events, for example, totalExpenses should be a field in a group, so that we don't need to find the sum of each expense per account everytime we read a group's expenses

* Reminders
- error handling should be first priority, make sure app is stable to exceptions
- validation for every field, each page should have validation regardless if its in a complete form
  + this means any switch between pages should first have validation for respective fields, to improve user experience and make sure user provides complete information

* MVP
** Basic Crud Functionality
- View expenses
- Add expenses
- Delete expenses
- Expense Class Model
  + Expense id
  + Expense name
  + Expense description (optional)
  + Expense amount
** Account creation
- Make account
- Login, Logout, Sign in
- Terminate account (deletes all expenses attached to that account)
- Account Class Model
  + Account id
  + Account username
** Groups
- Make groups
- Edit group name
- Add accounts to group
- Accounts can join group
- See total expenses in group (by all group members)
- Deletion of groups (deletes all expenses attached to group)
- Group Class Model
  + Group id
  + Group name
  + Group description
- Accounts can belong to multiple groups btw
** Sorting
- Sort by dynamic category
- Add category with creation of expense name
  + this would entail adding another field to expense model (expense category)
    * Updated Expense Class Model
      + Expense id
      + Expense name
      + Expense description (optional)
      + Expense amount
      + Expense Category
- Existing categories should show up with creation of groups, if category already exists, prevent user from creating category
  + Said validation tracking should be case insensitive
- Sorting in group view should work just the same as well
** Percentage of expenses in group
- View percentage of expended money of each account in a group

* Additional Features
** Additional metadata
- View creation time and date of expense
- View creation time and date of group
- View amount of members in a group
  + this would entail an addition in field for group (memberNumber) to track number of members in group, this field is updated appropriately and immediately with modification
** Summary Views
- access to a dashboard/summary page, view personal expenses as well as expenses spent in group
  + perhaps a chart showing what group you've expended most in, annoted in order by color and sorted in descending or ascending order
  + an extension of this could be something of a montly summary, showing summary of montly expenses, this should be low on the priority list though, could take a long time to implement
** Graphical improvements
- for percentages of expenses and such, use something like a pie chart
- summary view pages should have each account/category annotated by percentage/portion size
  + Example: user with most expended mula have red annotation, then second most have yellow, then third, green, etc.
** Budgets
- add budgets for groups and personally
  + visual indication when budget is exceeded
** Permissions and authorization
- account who created the group has special permissions
  + freely remove account from group
** Customization
- themes
** Advanced deletion
- delete all expenses in group, or remove yourself or leave from a group
- obviously expenses should be not be orphaned, when you leave all your expenses will go with you, or be deleted
  + an extension to this could be giving a dialog to choose whether you want your expenses to be deleted when you leave the group or just retained in your account as groupless extension
** Group Invitations
- change group joining to be decided by account instead of owner, owner can invite, account can accept or decline
** Bills
- bills are a mini group that can belong to a group or not, bills belong to multiple accounts, bills are used to atomic payments where it is clear who paid what
** Extra sort options
- Sort by minimum, maximum amount
- sort group by if you're in them or not, or if a user is in them or not
** All Expenses Page
- clicking on a category on categories page takes you to a page showing all expenses, whether they are in a group or not
- if they are in a group, annotate that they are
